# Kitternel Light v0.1.0-alpha.1

**Release notes prepared for review. No tag or GitHub Release is created by this
preparation.** The exact release commit/date must be recorded when the maintainer
publishes; do not mistake the preparation date for a release date.

Kitternel Light generates a complete, independently owned full-stack application:
Rust/Axum/Tokio, SQLx/SQLite, React/TypeScript, Vite/Tailwind CSS and standard Docker
and Compose. It is an early developer foundation, not production certification.

## Included

- Standalone generation using Python 3.11+ and Git: project identity, application
  source, Cargo/npm lockfiles, migrations, tests and deployment configuration.
- Public read-only greeting and separate liveness/readiness endpoints; validated
  runtime configuration, sanitized errors/logging and bounded HTTP shutdown.
- Compiled React frontend served by the same Rust process; loading, error and retry
  states, TypeScript validation, unit and real-backend browser tests.
- Multi-stage Docker build, non-root runtime and loopback-published Compose example
  with read-only root, dropped capabilities and a persistent SQLite data volume.
- SQLite WAL, foreign keys, FULL synchronization and embedded SQLx migrations.
- Own CI, offline pin checker, RustSec/npm/final-image scanning and sanitized
  reports with explicit failure policies.
- Consistent backup/export helpers and verified restoration into independent empty
  storage, preserving the original database.
- Independent README, CONTRIBUTING, MAINTENANCE, SECURITY and AGENTS documentation.

## First run

Follow the [root quick start](../../README.md#quick-start). Generation needs no host
Rust, Node or Docker; building/running with Docker requires BuildKit and Compose
v2. Native development requires the pinned toolchains plus a C compiler/linker.
Generated applications have their own license notice and do not require the source
starter afterward. No shared runtime, CLI, upstream remote or update controller is
installed or required.

## Support and compatibility

Linux/amd64, one application instance and local SQLite WAL-compatible storage are
the validated runtime model. See [platform and security limitations](ALPHA-LIMITATIONS.md)
for dated evidence and unverified environments. Dokploy/Coolify guides are proposed
configuration, not proof of tested deployments. No auth, sessions, authorization or
CSRF protection is included. No capacity, zero-downtime or recovery-time guarantee
is made.

This first alpha establishes no stable public API, generated-layout or migration
compatibility contract. Future starter releases may change those choices. The
starter tag `v0.1.0-alpha.1` does not rename generated applications' own package
versions (initially `0.1.0`, Cargo publishing disabled and npm private).

Generated source becomes your application. Kitternel does not automatically update
it and does not inherit responsibility for its deployment, security reports or
backups. Review dependency/base-image updates, retain immutable image identities,
add new migrations without rewriting history, prove recovery and assess database
compatibility before rollback. Image rollback does not undo migrations.

## Security and known risks

Read [SECURITY.md](../../SECURITY.md) and the
[known-risk register](ALPHA-LIMITATIONS.md). Temporary SQLx/minimatch choices,
vendor package findings and the previously observed Pebble executable remain
explicit review items. Scan counts are dated evidence, not an evergreen guarantee.
Scanner failures mean incomplete evidence, not a clean result. No suppressions or
threshold changes accompany this release preparation.

Before publication, the maintainer must complete the
[public-release checklist](PUBLICATION-CHECKLIST.md), including a verified private
reporting channel, name/privacy/attribution review, actual release commit and fresh
required validation. No historical scan result replaces that final review.
